200### What an action returns
201
202```
203tap e7 "Sign in" -> ok (XPath) · verified: pass
204check present "Welcome": met
205screen 4436bc · changed (+2 -0 ~0)
206+ e8 p "Welcome, a@b.c"
207+ e9 a "Orders" [tap]
208```
209
210- The first line gives the target, the keyword result with the locator
211 strategy that found it, and the verdict.
212- One line follows for each expectation.
213- The screen line is `unchanged`, `changed` with the added (`+`), removed
214 (`-`) and relabelled (`~`) rows, or `new screen` with every row. Pass
215 `screen="full"` for every row, or `screen="none"` for no screen line.
216- A ref never moves to a different element. A ref that is gone from the
217 screen is an error that lists the current rows.
218
219The verdict rule:
220
221| Result | `verified` |
222|--------|------------|
223| the keyword failed | `fail` |
224| no expectations | `unknown` |
225| every expectation met, and the screen changed or an `expect_present` that was not met before is met now | `pass` |
226| an expectation not met, and the screen did not change | `fail` |
227| an expectation not met, but the screen changed | `unknown` (the unmet checks are listed) |
228| the screen could not be read after the action | `unknown`; the expectations are not checked |
229
230Each acting tool also returns `structuredContent`:
231
232```json
233{"ok": true, "verified": "pass", "verb": "tap", "keyword": "press_element",
234 "target": {"ref": "e7", "label": "Sign in", "ladder": ["xpath=//button[normalize-space()='Sign in']"], "strategy": "XPath"},
235 "checks": [{"text": "Welcome", "expect": "present", "met": true}],
236 "screen": {"digest": "4436bc", "changed": true, "new_screen": false,
237 "added": [{"ref": "e8", "label": "Welcome, a@b.c", "cls": "p", "act": []}],
238 "removed": [], "relabelled": []}}
239```
240
241`error` (`{code, kind, message}`) is set when the call failed, `screen.rows`
242holds every row on a new screen, after an error and with `screen="full"`, and
243`result` holds the keyword's return value (for example from `get_text` through
244`run_keyword`).
245
246An action can run three times in a row without progress. The fourth identical
247action is refused with a `loop` error, and the keyword does not run. Progress is
248a `pass` verdict or a screen change. `observe`, `check` or a different action
249resets the count. `press_key`, read-only keywords, `press_keycode` and `sleep`
250do not count.

252### Build a reusable suite (there is no save tool)
253
2541. Read **`optics://session/{session_id}/steps`**: it lists the session's
255 actions with `modules_csv` and `elements_csv` rows for the steps that ran.
256 Secrets come back as `<redacted>`, so put them back before you run the
257 suite; see `optics://project-format` for the details.
2582. Read **`optics://project-format`** for the folder layout, `config.yaml`,
259 `${variables}` and escaping rules.
2603. Write the files. Parameterize by putting run-specific values in
261 `elements.csv` and referencing them as `${name}`. A cell that is exactly
262 `${name}` tries each of its values in order; `${name}` inside a longer value
263 is replaced by its first value.
2644. For loops, branches, computed values or API calls, write the control-flow
265 keywords (`Run Loop`, `Condition`, `Evaluate`, `Invoke Api`, …) into the

2675. Optionally lint the suite with the
268 [optics-framework-lsp](https://github.com/mozarkai/optics-framework-lsp)
269 language server: `optics-lsp lint <folder> --json`.
2706. Run it: `optics execute <folder>`. Results go to `execution_output/`. When a
271 step fails, `failed_steps_elements.json` holds the compact element list of the
272 screen it failed on.

424### Full toolset (`--toolset full`)
425
426The full toolset keeps the earlier surface for clients that call keywords by
427name: one string-typed tool per keyword of `ActionKeyword`, `AppManagement`
428and `Verifier` (each takes `session_id` and the keyword's params as strings),
429the `screenshot` tool, and the core `start_session`, `terminate_session`,
430`observe`, `tap`, `type_text`, `press_key`, `check` and `run_keyword`. The
431keyword tools `scroll` and `launch_app` replace the core tools with the same
432names. An element param of a keyword tool also accepts a ref from the latest
433`observe`.
