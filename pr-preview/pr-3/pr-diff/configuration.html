334=== "AI Self-Healing"
335
336 ### `ai_self_heal`
337
338 **Type:** `bool` | **Default:** `false`
339
340 Last-resort recovery for element location. When every locator strategy (XPath, text,
341 OCR, image) fails for a self-healing-capable keyword (e.g. `Press Element`, `Enter Text`),
342 a bounded LLM-driven loop reads the screen and attempts to recover before the keyword
343 fails outright.
344
345 Opt-in and inert unless an entry under `llm_models` is also enabled — a missing or
346 misconfigured LLM degrades this to a no-op rather than a failure:
347
348 ```yaml
349 ai_self_heal: true
350
351 llm_models:
352 - gemini:
353 enabled: true
354 ```
355
356 See [LLM Models](#llm-models) below for backend configuration.

809## LLM Models
810
811LLM backends power two opt-in features: the [`ai_self_heal`](#ai_self_heal) recovery path
812above, and `optics live`'s natural-language mode (`Ctrl-N`). Both stay inert until an entry
813below is enabled — the backend SDK is only imported when its engine is enabled, so leaving
814this section out has no cost for projects that don't use either feature.
815
816Each engine has an extra of the same name (`pip install 'optics-framework[openai]'`); the
817`llm` extra installs all three. Keys are read from environment variables only. If you enable
818more than one entry, a failed call falls through to the next one in list order.
819
820| You have | Engine |
821|----------|--------|
822| A Gemini API key, or Vertex AI | `gemini` |
823| An OpenAI key, OpenRouter, Azure OpenAI, or a local server (Ollama, vLLM, LM Studio) | `openai` |
824| A Claude key, or Claude on Amazon Bedrock / Google Vertex AI | `anthropic` |
825
826=== "Gemini"
827
828 **Purpose:** Google Gemini via the `google-genai` SDK, supporting both the Gemini
829 Developer API and Vertex AI. Install: `pip install 'optics-framework[gemini]'`.
830
831 ```yaml
832 llm_models:
833 - gemini:
834 enabled: true
835 capabilities:
836 model: gemini-3.8-flash # optional; framework default is gemini-2.5-flash
837 # temperature: 0.0 # optional; unset uses the model default (Gemini 3 recommends 1.0)
838 # use_vertexai: true # optional; else uses GOOGLE_GENAI_USE_VERTEXAI
839 # project: your-project # optional Vertex override; else GOOGLE_CLOUD_PROJECT
840 # location: us-east4 # optional Vertex override; else GOOGLE_CLOUD_LOCATION
841 ```
842
843 With no `capabilities` set, the SDK auto-detects everything from environment variables:
844
845 | Variable | Purpose |
846 |----------|---------|
847 | `GEMINI_API_KEY` / `GOOGLE_API_KEY` | Gemini Developer API key |
848 | `GOOGLE_GENAI_USE_VERTEXAI` | Switch to Vertex AI |
849 | `GOOGLE_CLOUD_PROJECT` | Vertex AI project |
850 | `GOOGLE_CLOUD_LOCATION` | Vertex AI location |
851 | `GOOGLE_APPLICATION_CREDENTIALS` | Vertex AI service account credentials |
852
853 !!! warning "Don't hardcode credentials"
854 `capabilities.api_key` / `capabilities.gemini_api_key` are also accepted but log a
855 warning when used — prefer the environment variables above so keys never end up in
856 a committed `config.yaml`.
857
858=== "OpenAI-compatible"
859
860 **Purpose:** any server that speaks the OpenAI Chat Completions API, via the `openai`
861 SDK. Without `url` it calls OpenAI; with one it calls that server instead.
862 Install: `pip install 'optics-framework[openai]'`.
863
864 ```yaml
865 llm_models:
866 - openai:
867 enabled: true
868 url: https://openrouter.ai/api/v1 # omit for OpenAI; or OPENAI_BASE_URL
869 capabilities:
870 model: anthropic/claude-sonnet-5-5 # required; the name the server uses
871 api_key_env: OPENROUTER_API_KEY # optional; default OPENAI_API_KEY
872 # response_format: json_object # for servers without JSON-schema output
873 # max_tokens: 4096 # optional cap per reply; unset = server default
874 # temperature: 0.0
875 ```
876
877 | Server | `url` | Key |
878 |--------|-------|-----|
879 | OpenAI | (omit) | `OPENAI_API_KEY` |
880 | OpenRouter | `https://openrouter.ai/api/v1` | `OPENROUTER_API_KEY` via `api_key_env` |
881 | Azure OpenAI | `https://<resource>.openai.azure.com/openai/v1/` | your Azure key via `api_key_env` |
882 | Ollama | `http://localhost:11434/v1` | none |
883 | vLLM / LM Studio | the server's `/v1` URL | none |
884
885 Natural-language mode and self-heal send screenshots, so pick a model that accepts
886 images. Responses use strict JSON-schema output by default; if the server rejects it,
887 set `response_format: json_object` and the schema is sent in the prompt instead.
