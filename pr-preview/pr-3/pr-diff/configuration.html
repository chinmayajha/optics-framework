335=== "AI Self-Healing"
336
337 ### `ai_self_heal`
338
339 **Type:** `bool` | **Default:** `false`
340
341 Last-resort recovery for element location. When every locator strategy (XPath, text,
342 OCR, image) fails for a self-healing-capable keyword (e.g. `Press Element`, `Enter Text`),
343 a bounded LLM-driven loop reads the screen and attempts to recover before the keyword
344 fails outright.
345
346 Opt-in and inert unless an entry under `llm_models` is also enabled — a missing or
347 misconfigured LLM degrades this to a no-op rather than a failure:
348
349 ```yaml
350 ai_self_heal: true
351
352 llm_models:
353 - gemini:
354 enabled: true
355 ```
356
357 See [LLM Models](#llm-models) below for backend configuration.

359=== "Natural-Language Agent"
360
361 ### `nl_agent`
362
363 **Type:** `object` | **Default:** `{vision: auto, max_steps: 15, escalation_model: ""}`
364
365 Settings of the natural-language mode of `optics live` (`Ctrl-N`). They have an effect
366 only when an entry under `llm_models` is enabled.
367
368 | Key | Meaning |
369 |-----|---------|
370 | `vision` | When the agent sends the screenshot. `auto` sends it on the first turn, after a step that code did not confirm, when the screen has few or unlabelled controls, and when no element list is available. `always` sends it on every turn. `never` sends no image, for text-only models. |
371 | `max_steps` | The most actions the agent takes for one instruction. |
372 | `escalation_model` | A model ID for the same engine as the first enabled `llm_models` entry. The agent sends hard turns to it: a second try after a bad reply, a turn after two failures in a row, and a turn with a guard note. Empty means one model for all turns. |

839## LLM Models
840
841LLM backends power two opt-in features: the [`ai_self_heal`](#ai_self_heal) recovery path
842above, and `optics live`'s natural-language mode (`Ctrl-N`). Both stay inert until an entry
843below is enabled — the backend SDK is only imported when its engine is enabled, so leaving
844this section out has no cost for projects that don't use either feature.
845
846Each engine has an extra of the same name (`pip install 'optics-framework[openai]'`); the
847`llm` extra installs all three. Keys are read from environment variables only. If you enable
848more than one entry, a failed call falls through to the next one in list order.
849
850Every engine takes `capabilities.timeout_s` (default `60`): the seconds one request may take.
851A request that takes longer fails like any other LLM error, so a stalled connection cannot hang
852a run. The `openai` and `anthropic` SDKs retry a timed-out request twice before it fails.
853
854| You have | Engine |
855|----------|--------|
856| A Gemini API key, or Vertex AI | `gemini` |
857| An OpenAI key, OpenRouter, Azure OpenAI, or a local server (Ollama, vLLM, LM Studio) | `openai` |
858| A Claude key, or Claude on Amazon Bedrock / Google Vertex AI | `anthropic` |

860=== "Gemini"
861
862 **Purpose:** Google Gemini via the `google-genai` SDK, supporting both the Gemini
863 Developer API and Vertex AI. Install: `pip install 'optics-framework[gemini]'`.
864
865 ```yaml
866 llm_models:
867 - gemini:
868 enabled: true
869 capabilities:
870 model: gemini-3.8-flash # optional; framework default is gemini-2.5-flash
871 # temperature: 0.0 # optional; unset uses the model default (Gemini 3 recommends 1.0)
872 # use_vertexai: true # optional; else uses GOOGLE_GENAI_USE_VERTEXAI
873 # project: your-project # optional Vertex override; else GOOGLE_CLOUD_PROJECT
874 # location: us-east4 # optional Vertex override; else GOOGLE_CLOUD_LOCATION
875 ```
876
877 With no `capabilities` set, the SDK auto-detects everything from environment variables:
878
879 | Variable | Purpose |
880 |----------|---------|
881 | `GEMINI_API_KEY` / `GOOGLE_API_KEY` | Gemini Developer API key |
882 | `GOOGLE_GENAI_USE_VERTEXAI` | Switch to Vertex AI |
883 | `GOOGLE_CLOUD_PROJECT` | Vertex AI project |
884 | `GOOGLE_CLOUD_LOCATION` | Vertex AI location |
885 | `GOOGLE_APPLICATION_CREDENTIALS` | Vertex AI service account credentials |
886
887 !!! warning "Don't hardcode credentials"
888 `capabilities.api_key` / `capabilities.gemini_api_key` are also accepted but log a
889 warning when used — prefer the environment variables above so keys never end up in
890 a committed `config.yaml`.

892=== "OpenAI-compatible"
893
894 **Purpose:** any server that speaks the OpenAI Chat Completions API, via the `openai`
895 SDK. Without `url` it calls OpenAI; with one it calls that server instead.
896 Install: `pip install 'optics-framework[openai]'`.
897
898 ```yaml
899 llm_models:
900 - openai:
901 enabled: true
902 url: https://openrouter.ai/api/v1 # omit for OpenAI; or OPENAI_BASE_URL
903 capabilities:
904 model: anthropic/claude-sonnet-5-5 # required; the name the server uses
905 api_key_env: OPENROUTER_API_KEY # optional; default OPENAI_API_KEY
906 # response_format: json_object # for servers without JSON-schema output
907 # max_tokens: 4096 # optional cap per reply; unset = server default
908 # temperature: 0.0
909 ```
910
911 | Server | `url` | Key |
912 |--------|-------|-----|
913 | OpenAI | (omit) | `OPENAI_API_KEY` |
914 | OpenRouter | `https://openrouter.ai/api/v1` | `OPENROUTER_API_KEY` via `api_key_env` |
915 | Azure OpenAI | `https://<resource>.openai.azure.com/openai/v1/` | your Azure key via `api_key_env` |
916 | Ollama | `http://localhost:11434/v1` | none |
917 | vLLM / LM Studio | the server's `/v1` URL | none |
918
919 Natural-language mode and self-heal send screenshots, so pick a model that accepts
920 images. Responses use strict JSON-schema output by default; if the server rejects it,
921 set `response_format: json_object` and the schema is sent in the prompt instead.
