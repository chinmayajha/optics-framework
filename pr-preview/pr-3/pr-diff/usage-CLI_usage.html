81### Selecting test cases
82
83Run a subset of a project's test cases without editing any file:
84
85```bash
86# Only these test cases
87optics execute ./my_project --include "Login Test" "Checkout Test"
88
89# Everything except these
90optics execute ./my_project --exclude "Legacy Flow"
91
92# Wildcards, and both flags together: every login test except the slow one
93optics execute ./my_project --include "login*" --exclude "Login Slow"
94```
95
96- **Names are matched case-insensitively** against the `test_case` column, and runs of whitespace count as a single space, so `"login TEST"` selects `Login Test`. A name must match the whole test case name; it is not a substring search.
97- **Wildcards:** `*` matches any run of characters and `?` matches exactly one. Every other character, including `[`, `]` and `.`, is literal.
98- **Several names:** give several names after one flag (`--include A B`), repeat the flag (`--include A --include B`), or both. Put the project folder **before** the flags (or end the flag's list with `--`), otherwise the folder is read as another test case name.
99- **Combining:** `--include` narrows the set first, then `--exclude` removes test cases from it.
100- **Setup and teardown always run.** Suite setup/teardown and per-test setup/teardown test cases are kept for whichever tests are selected, and they cannot be selected or excluded by name.
101- **Overrides config.yaml:** when either flag is given, the `include`/`exclude` lists in `config.yaml` are ignored for that run. Without flags, `config.yaml` applies as before.
102- **Typos fail fast:** a name that matches no test case stops the run before any device or browser session starts, with a `Did you mean '…'?` suggestion and the list of available test cases. A selection that leaves nothing to run is rejected the same way.
103
104The same flags work with [`optics dry_run`](#executing-dry-run), so you can check a selection before running it.
