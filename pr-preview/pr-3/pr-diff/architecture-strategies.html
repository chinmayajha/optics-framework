541### Assertion Polling
542
543`assert_presence` and `assert_visibility` poll in rounds until the timeout. Each round gives every strategy that can take the locator one non-waiting `check_elements()` call on the elements not yet found, cheap sources first, and stops at the first round that meets the rule (`all` counts each element once any source has found it). Rounds start at most once every 0.5 s, and the first round always runs in full. OCR and template matching share one screenshot taken in that round and run at most every 2 s while a cheaper strategy can still find every pending element.

837### Screenshot Streaming
838
839**Location:** `optics_framework/common/screenshot_stream.py`
840
841Screenshot streaming provides continuous screenshot capture for timeout-based element location operations. This is useful when waiting for elements to appear or when monitoring screen changes.

868#### Capture Process

870**1. Continuous Capture:**
871```python
872def capture_stream(self, timeout):
873 """
874 Continuously captures screenshots in a separate thread.
875
876 - Captures at maximum rate
877 - Stores in screenshot_queue
878 - Stops on timeout or stop_event
879 """
880 start_time = time.time()
881 while not self.stop_event.is_set() and (time.time() - start_time) < timeout:
882 frame = self.capture_screenshot()
883 self.screenshot_queue.put((frame, timestamp))

903**SSIM Deduplication:**
904- Uses Structural Similarity Index (SSIM) to detect duplicate frames

976#### Performance Considerations
977
978**Benefits:**
979- Non-blocking capture (doesn't slow down execution)
980- Deduplication reduces processing load
981- Queue-based (decouples capture from consumption)
982
983**Trade-offs:**
984- Memory usage (queues store frames)
985- CPU usage (deduplication computation)
986- Thread overhead
987
988**Optimization Tips:**
989- Adjust `max_queue_size` based on needs
990- Disable deduplication if not needed
991- Use appropriate timeout values
992- Clear queues between operations
